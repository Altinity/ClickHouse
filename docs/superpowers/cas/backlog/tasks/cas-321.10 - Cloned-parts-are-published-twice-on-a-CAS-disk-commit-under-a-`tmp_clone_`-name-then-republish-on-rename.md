## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
`cloneAndLoadDataPart` commits the clone under a temporary name inside `freeze`'s own transaction and the later rename republishes it. Callers: a mutation that skips an unchanged part (`MutateTask.cpp:3411` at antalya-26.6 @e2dd0f5d343), `REPLACE PARTITION`, `MOVE PARTITION`, `ATTACH PARTITION FROM`. Cost per cloned part: 2 manifest PUTs and 5 ref-log appends, of which 1 PUT and 3 appends are avoidable. `cloneAndLoadDataPart` also writes `metadata_version.txt` a second time as an autocommit write into the already committed clone (`MergeTreeData.cpp:10121-10128`).
Cut: in `freeze`'s owned transaction, not in the removal path. Read from the code, not measured.
Source: `docs/superpowers/reports/2026-09-30-cas-part-removal-flow/02-design-inputs.md`, parts B and C.
