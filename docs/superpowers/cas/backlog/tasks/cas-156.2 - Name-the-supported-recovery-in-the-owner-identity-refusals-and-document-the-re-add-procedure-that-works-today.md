## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
The refusals recommend a hand-delete that then hits a second refusal with no advice (`CA/Pool/CasServerRoot.cpp:556-561`).
Owed now, before the verb exists:
- Messages name `SYSTEM CAS DROP POOL MEMBER` / `clickhouse-disks cas-drop-member` as the supported verb, and the
  identity-lost refusal gets its own recovery sentence.
- Document the interim recovery: with the victim's mount object still present and the victim down, run
  `SYSTEM CAS DROP POOL MEMBER '<srid>' FROM DISK '<disk>'` (or `cas-drop-member` offline) from a surviving member; it adopts
  the uuid from the mount lease, empties the subtree, and warns harmlessly `slot tombstone failed: ... object absent before
  tombstone write`, clearing the slot for re-add.
- Document for k8s: keep the `uuid` file on a persistent volume. `operations/migration.md#decommission` covers permanent
  removal only.

Provenance: BACKLOG/mounts-and-lifecycle.md#operator-replica-readd-uuid-trap (the 'also owed' paragraph); verified 2026-09-26 against b1c34d03479 (cas-gc-rebuild) and 0dbbd797792 (altinity/antalya-26.6).
