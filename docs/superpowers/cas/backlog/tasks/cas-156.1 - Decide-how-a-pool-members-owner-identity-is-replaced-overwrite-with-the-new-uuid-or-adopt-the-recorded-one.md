## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
A server whose local uuid file was regenerated cannot mount its own pool; the refusal (`CA/Pool/CasServerRoot.cpp:546-551`)
lists three manual recoveries (restore the uuid file, a fresh `server_root_id`, delete the owner object by hand).
Options for the supported command:
- Overwrite the owner uuid: locks the original server out for good; must cover both owner and mount objects to keep the
  epoch-1 re-mint guard armed.
- Adopt the recorded owner uuid and mount as it, as `Pool::openForDecommission` already does (`CA/Pool/CasPool.cpp:974`);
  looks strictly better.
No `force_owner_claim` exists in `src/`. Folded 2026-08-04 triage asks: a concrete `force_owner_claim` proposal, an audit
record of each forced claim, and telling post-mortem recovery from live misuse. Not the read-only mount task.
