## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Any throw from `ContentAddressedMetadataStorage::startup` (`CA/ContentAddressedMetadataStorage.cpp:839`) escapes
`DiskSelector::initialize` (`src/Disks/DiskSelector.cpp:91-141`), which shuts the disks down and rethrows, so the server exits.
Two triggers are known:
- B208: the mount probe times out during a transient S3 outage at startup; the server exits 243 with no retry.
- The residual-data guard refuses to bootstrap over a non-empty prefix without `_pool_meta` (668, "missing _pool_meta over a
  non-empty pool prefix", `CA/Pool/CasPool.cpp:468`); the container exits 156.
The refusal itself is correct and must stay; only its blast radius is wrong. Direction: mark the one disk not mounted and keep
the node up, with a bounded startup retry for the transient case. Decision owed: bounded retry, degraded start, or both.
Not a gate for durability: S40 only requires acked data to survive on the live replica.

Provenance: BACKLOG/mounts-and-lifecycle.md#mount-fence [B208] and #pool-refusal-node-fatal; verified 2026-09-26 against b1c34d03479 (cas-gc-rebuild) and 0dbbd797792 (altinity/antalya-26.6).
