## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
The two liveness definitions disagree on purpose. `system.cas_mounts` shows `expired` from wall-clock arithmetic
(`CA/Pool/CasServerRoot.cpp:1209-1216`). `NoWait` decommission needs a certificate of death that trusts no wall clock:
`gc_fenced`, the clean-farewell marker, or a proven-dead token (`:846`); `NoWait` passes none, so a hard-killed member is
removable only after a GC round fences it. The refusal still says "stop the server or wait for its lease to lapse"
(`CA/Pool/CasPool.cpp:754-768`), which is not enough.
The test side is settled (`d181a54a1dd` retries through the refusal). Open: either the refusal names the real precondition
(`state = 'fenced'` in `system.cas_mounts`, which needs GC running on some member), or `NoWait` accepts a hard-killed member
some other way. Do not weaken the certificate-of-death rule: it keeps a live twin from being decommissioned across two clocks.

Provenance: BACKLOG/mounts-and-lifecycle.md#decommission-wrong-predicate (PR 2073 amd_tsan 4/6); verified 2026-09-26 against b1c34d03479 (cas-gc-rebuild) and 0dbbd797792 (altinity/antalya-26.6).
