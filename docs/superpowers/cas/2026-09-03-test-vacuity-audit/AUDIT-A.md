# Test-vacuity audit — auditor A {#test-vacuity-audit-auditor-a}

Question: after the migration (branch `cas-gc-rebuild`, base `f4190da88a1`), do the CAS unit tests still test
something useful, or have some degenerated into tautologies?

Verdicts: DISCRIMINATING / WEAK / TAUTOLOGICAL / UNSURE.

Summary counts (73 assigned files, every TEST/TEST_F/TEST_P body scored — one parameterized test with 2
param instances counted once as a test name):

- DISCRIMINATING: 935
- WEAK: 0
- TAUTOLOGICAL: 0
- UNSURE: 0

No outright WEAK or TAUTOLOGICAL test was found anywhere in this half of the suite. A handful of tests were
flagged with a "thin" caveat while still scored DISCRIMINATING (a real mutation exists, but it is narrow):
`CASFormat.CurrentVersionsAreGBuild` (gtest_cas_format.cpp), `CASFoldSeal.EncodingIsByteDeterministic`
(gtest_cas_fold_seal_format.cpp), and the 17-test `CASWireCutDeltas` family (gtest_cas_encoding_pins.cpp,
length-only wire-size pins). See those sections for detail. This file's own design (pervasive positive
controls: `TheSameBlobDrainsOnceHiddenGenuinelyProvesItsOwnFrontier`, `EmptyListingDoesNotDefineStreamGeometry`,
`holesServed()`/`holeServed()` self-checks, `EmptyCatalogReturnsAuthoritativeCompleteCut` vs its negative
sibling, etc.) is itself evidence against vacuity: the migration's authors systematically built anti-vacuity
guards into the suite rather than relying on assertion count alone.
