# CA Core M-C3 — `Cas::Gc` Regular GC Tail Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** `Cas::Gc::runRegularRound` — the leader-paced, split-brain-safe regular garbage-collection round (fold → retire → fence → recheck → exact-token delete + outcomes + cascade + journal trim) over the green M-C2 core, with a fault-injection harness that gives the model's headline GC-vs-publish scenarios mechanical coverage.

**Architecture:** A new `DB::Cas::Gc` class drives one round against `Cas::Backend` + the M-C2 `Store`. The publish gate already consumes the retire sets via `RetireView` (M-C2) — M-C3 only writes them. Every step is idempotent on replay from durable state (a crashed round re-runs to a no-op). The full-GC walk, debris reclaim, and packs are deferred to M-F (API slot reserved).

**Tech Stack:** C++ (Allman braces — CI-enforced), gtest (`src/Disks/tests/`, auto-globbed), strict-JSON metadata codecs via the M-C2 `CasCodecUtil.h` toolkit, `CityHash_v1_0_2` for hash-prefix sharding, the M-C2 `Store::mutateShard` CAS loop (reused via `friend`), `Cas::InMemoryBackend` fault hooks (`setHoldDeletes`/`landPendingDelete`, `failNextCasPut`) for the interleaving harness.

## Decisions recorded in this plan {#decisions}

| Decision | Choice | Rationale |
|---|---|---|
| Snap sharding | by **target content-hash prefix** (`snap_shard = u64(hash[:8]) % snap_shards`), `snap_shards` a GC constant in CAGS v2, **default 1** | every edge targeting a node lands in the node's OWN snap shard ⇒ in-degree is intra-shard, no cross-shard aggregation (user decision 2026-06-11, spec §4 pinned). NOT root-shard: a content object's in-degree is global across roots and parent trees. |
| Snap object | one JSON object per `(generation, snap_shard)`; M-C3 default 1 shard ⇒ effectively one snap object, but the shard dimension is correct by construction | correctness-first; scale-out is just raising `snap_shards`. |
| Fold model | **incremental** — durable snap + per-root-shard `folded_cursor`; each round folds journal deltas `(folded_cursor, shard_version]` | O(delta), and journal trimming + `INV-JOURNAL-COVERAGE` require `folded_cursor`. The full-GC authoritative rebuild is M-F. |
| Root-shard discovery | **SUPERSEDED (2026-06-12, after the Task-8 adversarial review):** discovery reads the NAMESPACE REGISTRY (`roots/_registry`, spec §4) — never LIST; the universe is registered namespaces × ALL `root_shards` shards. R3 fences the registry first, then every shard (minting fence-only manifests for absent ones); writers register a namespace before its first publish (`W-REGISTER`, gate floor). The original LIST + present-only-fence plan left first-publish-to-an-absent-shard unordered against the fence — a reachable dangle once the delete lands. `Layout::rootsPrefix`/`tryParseRootShardKey` remain for tests/M-F. |
| Lease | S3-only CAS lease in `gc/state` (`owner`, `seq`); CAS-stolen after observed non-renewal; **every round step is idempotent under split-brain** (monotone state + unique-path logs + exact-token deletes) | spec §7; Keeper acceleration is out of scope. Tests inject split-brain with two `Gc` instances. |
| Cascade | **same-round pipeline step** (strip a deleted tree's child edges + clear its marker, before any later fold beyond R's fence versions) | spec §7 "cascade is a pipeline step, not a foldable record" — closes the cascade-vs-recreate race. |
| Fence write | reuse `Store::mutateShard` (bumps `shard_version`, no journal record); record `fence_version[R][root_shard]` = the committed `shard_version` | reuses the verified CAS loop; a `shard_version` bump with no journal record is a fold no-op and harmless to `INV-JOURNAL-COVERAGE`. |
| Journal trim | a manifest CAS dropping journal records with `at_version <= folded_cursor[root_shard]` | `INV-JOURNAL-COVERAGE`: trim only what a durable `folded_cursor` advance covers; never "to compact". |
| Deferred to M-F | full-GC walk, debris reclaim (heartbeat classification), packs/repack, `gc/checkpoint`, `checkpoint_generation` | API slot reserved; the snap rebuild + debris tail need the authoritative `LIST` walk, out of M-C3 scope. |

## Edge model (the heart — read before Task 3) {#edges}

Spec §7 edge identities, mapped to C++:

```text
root edge:  (root_shard, part_name) -> (Tree, T)          // one per (ns/shard, part_name)
tree edge:  (parent_T)              -> (child_kind, child_hash)   // one per distinct child of T
pack edge:  (T)                     -> (Pack, pack_hash)   // one per distinct referenced pack of T
```

In-degree(node) = number of distinct present edges whose TARGET is that node. Set semantics: an edge is identified by a canonical id string; re-adding an identical edge is a no-op (no double-count). **GC state may over-count, must never under-count** (`INV-OVER-COUNT-ONLY`) — every failure delays reclamation, never accelerates a delete.

Sharding: an edge is stored in the snap shard of its TARGET (`snap_shard = hashPrefixShard(target_hash, snap_shards)`). So all edges targeting a node live in that node's shard ⇒ its in-degree is computed from one shard. Expanding a tree `T` (hash in shard A) emits child edges that land in the CHILDREN's shards (B, C, …); the expansion MARKER for `T` lives in shard A. So one fold may load/modify several snap shards.

`known(node)` = the node has appeared as an edge target at least once (journal-known). A **candidate** is a `known` node whose in-degree transitioned to 0. Fresh uploads are never `known` until a journal `+` references them ⇒ never candidates (spec §7 R1).

```cpp
enum class EdgeKind : uint8_t { Root = 1, Tree = 2, Pack = 3 };

struct Candidate { ObjectKind kind = ObjectKind::Blob; UInt128 hash{}; };

/// snap_shard = low 64 bits of the hash, mod snap_shards (snap_shards >= 1).
uint64_t hashPrefixShard(const UInt128 & hash, uint64_t snap_shards);

class GcSnap
{
public:
    uint64_t snap_shard = 0;
    uint64_t generation = 0;

    /// edge mutation — set semantics by canonical id; returns nothing on add.
    void addRootEdge(const String & root_shard, const String & part_name, const UInt128 & tree);
    void addTreeEdge(const UInt128 & parent_tree, ObjectKind child_kind, const UInt128 & child_hash);
    void addPackEdge(const UInt128 & parent_tree, const UInt128 & pack_hash);

    /// edge removal — returns nodes whose in-degree TRANSITIONED to 0 (candidates), known-only.
    std::vector<Candidate> removeRootEdge(const String & root_shard, const String & part_name, const UInt128 & tree);
    std::vector<Candidate> removeTreeEdge(const UInt128 & parent_tree, ObjectKind child_kind, const UInt128 & child_hash);

    /// strip ALL edges sourced from parent_tree (cascade) + clear its marker; returns newly-zero children.
    std::vector<Candidate> stripTree(const UInt128 & parent_tree);

    void markExpanded(const UInt128 & tree);
    bool isExpanded(const UInt128 & tree) const;

    uint64_t inDegree(ObjectKind kind, const UInt128 & hash) const;
    bool isKnown(ObjectKind kind, const UInt128 & hash) const;

private:
    /// every edge keyed by its canonical id; the value carries the target so we can recompute in-degree.
    struct EdgeRec { EdgeKind edge_kind; ObjectKind target_kind; UInt128 target_hash{};
                     String root_shard; String part_name; UInt128 parent_tree{}; };
    std::map<String, EdgeRec> edges;                          /// edge_id -> record
    std::set<UInt128> expanded;
    std::set<std::pair<uint8_t, UInt128>> known;
    /// derived index: (kind,hash) -> count of present edges targeting it (kept in sync with `edges`).
    std::map<std::pair<uint8_t, UInt128>, uint64_t> indeg;

    friend String encodeGcSnap(const GcSnap &);
    friend GcSnap decodeGcSnap(std::string_view);
};

String encodeGcSnap(const GcSnap & snap);
GcSnap decodeGcSnap(std::string_view data);
```

Implementation notes (`CasGcSnap.cpp`):
- Canonical edge id (a plain `String`, never hashed — just a map key): Root ⇒ `"R|" + root_shard + "|" + part_name`; Tree ⇒ `"T|" + u128ToHex(parent_tree) + "|" + to_string(uint8_t(child_kind)) + "|" + u128ToHex(child_hash)`; Pack ⇒ `"P|" + u128ToHex(parent_tree) + "|" + u128ToHex(pack_hash)`. (Root id need not include the target because a `(root_shard, part_name)` maps to exactly one tree at a time; a re-point is remove-old + add-new. Tree/Pack ids include the target.)
- `addX`: insert into `edges` if absent (set semantics); if newly inserted, `++indeg[target]` and `known.insert(target)`.
- `removeX`: erase from `edges` if present; if erased, `--indeg[target]`; if `indeg[target]` reaches 0 AND `known` has it ⇒ return it as a `Candidate` (and erase the 0 entry from `indeg`).
- `stripTree(T)`: erase every edge whose `parent_tree == T` (Tree/Pack edges), decrement each target's in-degree, collect newly-zero known targets; clear `expanded.erase(T)`. Return the collected candidates.
- `inDegree` reads `indeg` (0 if absent); `isKnown` reads `known`.
- Codec via the strict-JSON toolkit; `edge_kind`/`target_kind` enum↔string helpers (`"root"/"tree"/"pack"`, `"blob"/"tree"/"pack"`); decode rebuilds `edges`/`indeg`/`known`/`expanded` (recompute `indeg` from the decoded edges; `known` from the explicit list). Bad enum / future version / unknown key ⇒ `CORRUPTED_DATA`/`NOT_IMPLEMENTED` per the toolkit.
