# M-W — CA Cutover Implementation Plan {#m-w-plan}

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans (direct execution per
> the standing 2026-06-12 directive — subagents only for mechanical work such as build-log analysis).
> Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Rewrite the wiring layer onto the green `DB::Cas` core (M-C1..M-C3), retarget
fetch-by-relink, give `DataPartsExchange` a purpose-built façade, delete the superseded PoC
machinery, and switch the CA-S3 test environment from MinIO to RustFS — ending with the SQL-level
acceptance suites green.

**Architecture:** per design `docs/superpowers/specs/2026-06-11-ca-core-refactor-design.md` §4
(wiring = thin translators over the `Cas::` public API; policy is data, not protocol) and §5
(deletion inventory). Protocol spec: `2026-06-10-ca-incarnation-store-design.md`. No compatibility
with the PoC pool layout is preserved (never published).

**Tech stack:** existing `IMetadataStorage`/`IMetadataTransaction` seam (kept), `DB::Cas` core,
gtest wiring tier against `Cas::InMemoryBackend`, praktika for SQL acceptance, RustFS
`1.0.0-beta.8` (probed green 2026-06-11) for the CA-S3 lane.

## Decisions fixed for M-W (decision record) {#m-w-decisions}

These resolve the design's "decided in M-W" items. Each is recorded here so tasks never re-litigate:

- **D-W1 Namespace mapping.** `RootNamespace = "<server_id>/<table_uuid>"` for live parts;
  `"<server_id>/detached/<table_uuid>"` for detached; `"shadow/<backup_name>/<table_uuid>"` for
  FREEZE (shadow is pool-global, not per-server — backups are read by any replica). Ref name =
  `<part_dir_name>` (the directory name, e.g. `all_1_1_0`). The core treats all of these as opaque
  strings (`checkNamespace` allows `/`).
- **D-W2 Build lifecycle.** ONE `Cas::Build` per written part, opened lazily at the first staged
  write for that part (W-HEARTBEAT needs the heartbeat durable before the first PUT — buffer
  finalize uploads immediately, so the Build must exist then, NOT at commit). `publish` at commit;
  `Build::abandon` for every still-open Build in the transaction destructor (uncommitted ⇒ debris,
  heartbeat-gated — replaces B52 pins).
- **D-W3 Mutable per-part files** (`uuid.txt`, `txn_version.txt`, `metadata_version.txt`) live in
  `RefPayload.mutable_files` (a `std::map<String,String>` — already in the core's `RefPayload`).
  Writes to a NOT-yet-committed part stage into the Build's pending payload; writes to a COMMITTED
  part go through `Store::updateRefPayload` at commit. The `.meta` sidecar key family is deleted.
- **D-W4 Relink protocol.** The sender transmits `{pool_uuid, tree_id}` (replica-internal wire
  fields; the old `part_id` cookie field carries the tree id hex — same size class, no protocol
  version bump needed on this branch). The receiver: same `pool_uuid` ⇒ `startBuild` +
  `adoptTree(tree_id)` + `publish(ns, part_name, tree_id, payload-from-fetch-header)`; adoptTree
  now HEAD-observes (cold reuse, 2026-06-12), so "tree reclaimed meanwhile" surfaces as
  `FILE_DOESNT_EXIST` ⇒ fall back to the byte fetch — exactly where the old 4-step pin fell back.
  `relinkPin/relinkRevalidate/relinkPublishRef/relinkReleasePin` and `WriteSession` are deleted.
- **D-W5 GC scheduler config.** Keep knob names `content_addressed_gc_enabled` (default 1) and
  `content_addressed_gc_interval_sec` (default 60); DELETE `content_addressed_gc_grace_sec` (the
  incarnation protocol has no grace window — the fence/recheck handshake replaces it). The
  scheduler owns a random `gc_id` (u128, minted at startup) and calls `Gc::runRegularRound` on the
  interval; lease dedup makes multi-mounter pools safe, so `allow_shared_pool` gating of GC is
  GONE (every mounter may run the scheduler; the lease picks one leader).
- **D-W6 Pool identity.** `pool_uuid` = the core's `PoolMeta::pool_id` (from `_pool_meta`, created
  by `Store::open` on a fresh pool). The PoC's `claimPoolOwnership`/`PoolCoordination` is deleted;
  `allow_shared_pool` disappears from the wiring ctor (the protocol is multi-writer by design).
- **D-W7 In-place rewrite.** File names `ContentAddressedMetadataStorage.{h,cpp}`,
  `ContentAddressedTransaction.{h,cpp}`, `ContentAddressedWriteBuffers.{h,cpp}` keep their names
  and registration; contents are rewritten. New small files: `PartPathParser.{h,cpp}`,
  `ContentAddressedExchange.h` (the façade), `CasGcScheduler.{h,cpp}`. Everything else in the
  deletion inventory (T12) goes.
- **D-W8 RustFS fixture.** The CA-S3 stateless lane runs RustFS pinned at `rustfs/rustfs:1.0.0-beta.8`
  on a dedicated port (so MinIO keeps serving the non-CA s3 disks of the same server config),
  bucket `test`, path-style; the CA-S3 policy XML endpoint moves to that port. Integration-test CA
  fixtures get a `with_rustfs`-style cluster option only if an existing CA integration test needs
  the delete tail (checked in T13; if none, integration stays MinIO until M-F and that is recorded).

### Task 2: read-side `ContentAddressedMetadataStorage` on `Cas::Store` {#t2}

**Execution findings (recorded 2026-06-12, before starting T2):**

- **T2 is the STRUCTURAL SWAP, not just the read side.** The old transaction compiles against the
  old storage's private members (friend access to `resolveBlobEntry`, `gcLogWriter`, relink
  machinery), so the storage cannot be rewritten alone. T2 therefore: rewrites BOTH classes (the
  transaction lands as a compiling SKELETON whose ops throw `NOT_IMPLEMENTED` until T3-T8 fill

  `DataPartsExchange` seam with SAFE DEGRADATIONS (sender offers no relink ⇒ receiver does byte
  fetch — correct, just slower) until T11. Green-between-tasks holds at the build+unit level; SQL
  behavior returns task by task and is gated at T13 (per design D3: ONE cutover milestone).
- **Serving manifest-embedded bytes (mutable per-part files; future inline placement):**
  `DiskObjectStorage::prepareRead` is the read entry (`IDisk::readFile` → `prepareRead` →
  `metadata_storage->getStorageObjects` → object-storage stack). There is NO production inline
  mechanism on this path (`readInlineDataToString` has no disk-read consumer). The mechanism:
  `ReadPipeline::setSource(BufferCreator, StoredObjects, ReadSettings)` (src/IO/ReadPipeline.h:111)

  storage resolves the path to in-manifest bytes, builds the pipeline from an owned-string

  paths (PoC contract kept); the wiring re-splits `file` into `<detached_part>` + `<file>` and
  routes to the detached namespace. All B36/B46/B62/B64 read branches re-derive naturally
  (detached part dir exists = resolveRef hit in the detached namespace, etc.).
