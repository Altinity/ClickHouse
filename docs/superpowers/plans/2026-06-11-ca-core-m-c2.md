## Amendment (2026-06-11, user decision after Task 6) {#amendment-json}

Two format decisions landed mid-milestone, executed as **Task 6.5** between Tasks 6 and 7:

1. **Envelope header checksum: CityHash64, not CRC-32C.** The `u32 header_crc32c + u32 reserved0` pair at
   `[88, 96)` becomes `u64 header_hash` = `CityHash64` over the 96 core-header bytes with the field zeroed
   (the hash family the rest of ClickHouse uses; the hand-rolled CRC-32C table is deleted). Diagnostics-quality
   check, not a safety dependency — every load-bearing header field is independently re-verified.
2. **Strict JSON for all non-hashed metadata objects** (root manifests `CARS`, `gc/state` `CAGS`, retired sets
   `CART`, heartbeats `CAHB`, `_pool_meta`, future checkpoints/outcomes): top-level object with `format` +
   `version` fields; fail-closed parsing (unknown/missing key, wrong type, wrong format, malformed ⇒
   `CORRUPTED_DATA`; newer version ⇒ `NOT_IMPLEMENTED`). Hashed objects (CHCA envelope, tree payload `CATR`,
   blob/pack payloads) stay binary. Task 7's `_pool_meta` therefore uses JSON, not the `key=value` text
   sketched below; Tasks 8–13 consume the JSON codecs unchanged through the same C++ structs/functions.

Spec updated accordingly (§3.1 byte table + checksum policy; §4 encoding split). The binary CAGS/CART/CAHB
byte tables in Tasks 4 and 6 below are SUPERSEDED by the JSON encodings; the C++ surface (structs, function
names, strictness rows, tests' semantics) is unchanged.

## Decisions recorded in this plan (design §9 open items) {#decisions}

| Constant / choice | Value | Rationale |
|---|---|---|
| Root shards per namespace `N` | pool-wide, default **8**, fixed at pool creation, stored in `_pool_meta` | keeps each manifest at ~1/8 of a table's per-server parts (O(100) refs ≈ tens of KiB); pool-wide because per-namespace metadata objects would add a read to every cold resolve; resharding is out of v1 (spec §4) |
| Ref→shard hash | `CityHash64(ref_name) % N` | same family as content hashing; stability is per-pool (recorded via `format_version`) |
| Manifest size guard | soft **16 MiB** (`LOG_WARNING`), hard **64 MiB** (throw `LIMIT_EXCEEDED`) | spec §4 requires "size guard + alert"; hard cap fails the publish before the backend rejects unwieldy CAS bodies |
| Blob object `header_len` | **fixed 256 bytes** for `kind=blob`, padded with zero-type TLV; recorded in `_pool_meta` (`blob_header_len`) | makes `Store::locate` a constant shift (spec §6 "payload offsets are header_len-shifted constants" — no per-blob header read on the hot path). 96 core + 33 PROVENANCE TLV leaves ~119 bytes for `INTENDED_REF`; if it does not fit it is **truncated to fit (or dropped)** — it is diagnostic-only (spec §3.1). Trees/packs are exempt: trees are read whole; pack slices carry absolute offsets |
| `domain_id` | = `pool_id`, a random `UInt128` minted at pool creation, stored in `_pool_meta` | one trust domain per pool; envelope `domain_id` validation gets a concrete value |
| Retryable publish abort | `ErrorCodes::ABORTED` | thrown when W-REVALIDATE finds a dependency absent and the `Build` has no payload source to re-create it (only possible for reuse/adopt deps; the caller retries the whole operation — fail-closed, no substitute) |
| Resurrect mechanics | GET full object → rewrite header (fresh `incarnation_tag`, same `header_len`) → `putOverwrite` (`If-Match`) | works for every size; the server-side multipart copy-to-self optimization for huge blobs (spec §5 step 2) is deferred to M-F — record a `/// FOLLOW-UP(M-F)` comment at the resurrect site |
| Journal trimming | none in M-C2 | trimming requires `folded_cursor` (`INV-JOURNAL-COVERAGE`), which is GC state — M-C3. The size guard above bounds the damage; note this in `CasStore.h` |

```cpp
/// Streaming conditional create (If-None-Match:* semantics). The caller writes the FULL object body
/// (envelope header + payload) into buffer(), then calls finalize() exactly once:
///   - Done                ⇒ the object is durable; out_token (if requested) is the new incarnation's token
///   - PreconditionFailed  ⇒ the key already existed — NOTHING was changed (same contract as putIfAbsent)
/// finalize() may throw on storage errors; PreconditionFailed is an OUTCOME, never an exception.
/// cancel() (or destruction before finalize) abandons the upload: the key is never created by it.
class WriteSink
{
public:
    virtual ~WriteSink() = default;
    virtual WriteBuffer & buffer() = 0;
    virtual PutOutcome finalize(Token * out_token) = 0;
    virtual void cancel() noexcept = 0;
};

using WriteSinkPtr = std::unique_ptr<WriteSink>;
```

and the pure virtual inside `Backend`:

```cpp
    /// Streaming variant of putIfAbsent — see WriteSink. Large content blobs use this; whole-String
    /// ops remain for manifests, trees, probe and GC objects.
    virtual WriteSinkPtr putIfAbsentStream(const String & key) = 0;
```

### Task 2: Typed S3 precondition signal + `ObjectStorageBackend` streaming sink {#task-2}

Retires deferral 2 and makes the Local instantiation green again.

Background (verified during planning): a 412 is an UNMODELED error for the AWS SDK — `Aws::S3::S3Errors` has no `PRECONDITION_FAILED` value, so `outcome.GetError().GetErrorType()` is `UNKNOWN` and the only machine-readable discriminator is `outcome.GetError().GetExceptionName()`, which carries the canonical S3 error code string (`"PreconditionFailed"`, `"NoSuchKey"`, …) from the response XML `<Code>`. `WriteBufferFromS3` already branches on it for logging (`src/IO/WriteBufferFromS3.cpp:790`) but throws an `S3Exception` that DROPS the name. The typed signal = carry the name on the exception, and match it EXACTLY in the backend (replacing M-C1's substring matching over `e.message()`, which was contaminated-prone).

### Task 4: GC-surface formats — "CAGS" gc/state v1 + "CART" retired-set v1 {#task-4}

Minimal versioned codecs so the publish gate can read what GC will write. **Ownership note for the file header comment:** M-C3 owns these formats and will extend them (cursors, lease, fence versions ⇒ CAGS v2); M-C2 defines exactly what the WRITER needs. Decode is strict per the M-C1 convention: bad magic / truncation / trailing bytes ⇒ `CORRUPTED_DATA`; future version ⇒ `NOT_IMPLEMENTED`.

**Files:**
- Create: `Core/CasGcFormats.h`, `Core/CasGcFormats.cpp`
- Test: `src/Disks/tests/gtest_cas_gc_formats.cpp`

Normative byte tables (little-endian, like every M-C1 codec):

```text
gc/state ("CAGS" v1):
  char[4]="CAGS"  u8 version=1  u8[3] reserved=0
  u64 round            // the highest GC round whose retire sets are durable
  u64 fence_seq        // leadership-epoch component of retired-set paths (spec §4)

retired set ("CART" v1), one object per gc/retired/<round>.<fence_seq>/<shard>:
  char[4]="CART"  u8 version=1  u8[3] reserved=0  u64 entry_count
  entry: u8 kind{1=blob,2=tree,3=pack}  u128 hash  u8 token_type{1=etag,2=generation,3=emulated}
         u16 token_len  token_len bytes (token value)  u64 size
```
