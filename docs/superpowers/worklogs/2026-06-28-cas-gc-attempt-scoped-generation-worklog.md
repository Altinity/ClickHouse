**Reconciliation note (SUPERSEDED — see correction below).** Initial draft attempt-scoped only the four `gc/gen/<gen>/…` keys and left retired/outcomes under `gc/retired/`+`gc/outcomes/` (already `fence_seq`-keyed), calling deposed-leader retired debris "bounded sweep, minor."

**CORRECTION (user review 2026-06-28 — authoritative, reverts to the spec):** that deviation was **unsafe and is rejected**. Reasons (verified in code):
- `retired` is **not** just a GC-internal log — it is a **writer-facing publish-gate input**: `RetireView::refresh()` LISTs the whole `gcRetiredPrefix()` (`CasRetireView.cpp:46`) and writers consult `store->retireView().isCondemnedToken(...)`/`.round()` on the commit path (`CasBuild.cpp:235,414,666,725`). A stale retired set written by a deposed leader (under its own `(round, fence_seq)`) survives in that LIST and **influences live writers** → directly violates *"no unadopted artifact may ever influence a decision."*
- On a steal that bumps `fence_seq`, `tryResumeIncompleteRound` looks for retired sets at the **new** `(round, fence_seq)` (`CasGc.cpp:1360`) and can miss the deposed leader's stale sets → they are never dropped → permanent writer-visible debris. There is **no** existing sweep for stale `gc/retired/`+`gc/outcomes/` (Finding 4 — generation-retention only touches `gc/gen` artifacts; recheck drops only the current key).
- **DECISION:** follow the spec exactly — **all** decision-bearing round artifacts, *including `retired` and `outcomes`*, move under `gc/gen/<g>/attempt/<a>/…` and resolve via `(snap_generation, snap_attempt)`. `RetireView` resolves retired sets under the accepted attempt instead of LISTing `gc/retired/`. This also **simplifies cleanup**: the wholesale `gc/gen/<g>/` retention prune reclaims retired/outcomes automatically — no separate sweep, no separate proof.
- Spec key layout (lines 102-106): `retired` under `gc/gen/<G_f>/attempt/<a>/retired/<round>/<shard>`; `outcomes` under `gc/gen/<G_c>/attempt/<a>/outcomes/<round>/<shard>`.
- **TLA+ correction:** `attempt` must be modeled as a **fresh monotonic attempt id** (abstract `lease.seq` counter minted per fold), NOT the leader's identity — a leader id is not unique across rounds/steals, so leader-id scoping would mask collision/resume/pruning bugs. The model must also represent the **retired-set visibility** (the RetireView LIST) so the proof covers the writer-facing leak, not just the GC-internal seal.

Scope added by the correction: `CasRetireView.cpp`/`.h` (writer-facing reader), retiredKey/outcomesKey become `(generation, attempt, round, shard)`-scoped, and the doc comments in `CasGcOutcomes.h`/`CasGcFormats.h`/`Proto/cas_format.proto`.
